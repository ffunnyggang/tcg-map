# iOS / Android 다음 빌드 — 전체 화면 딤 통일

등록: 2026-10-24 (KST)
상태: 요건 등록 / 구현·빌드·단말 QA 미착수. 다음 iOS 및 Android 빌드 QA 필수 항목.

## 관찰된 현황 (사용자 단말 확인)

- 바인더 자랑하기 신고: 웹 콘텐츠에만 딤 적용. 네이티브 헤더와 상태바까지 확장 필요.
- 일반 TALK 게시물 신고: 콘텐츠 딤 2겹, 헤더 딤 1겹, 상태바 딤 없음.
- 차단하기: 시스템 확인 팝업은 이미 상태바까지 정상 딤 처리. 현재 OS 처리를 유지하며 추가 딤을 중첩하지 않는다.

## 구현 및 완료 기준

- [ ] 신고 바텀시트가 열리면 콘텐츠 + 네이티브 헤더 + 상태바 배경을 끊김 없이 동일한 농도로 딤 처리.
- [ ] 웹/네이티브 딤 책임을 구분해 각 화면 영역에 시각적으로 한 번만 적용. 일반 게시물 콘텐츠의 이중 딤 제거.
- [ ] 바인더 별도 인앱 페이지와 TALK 탭/상세 경로 모두 팝업 열림·닫힘을 네이티브에 동기화.
- [ ] 팝업이 열려 있는 동안 뒤쪽 콘텐츠와 헤더 버튼 터치 차단. 바텀시트 자체는 딤 처리하지 않음.
- [ ] 닫기, 바깥 영역 터치, 신고 완료/실패, Android 뒤로가기, 페이지 이탈, 앱 백그라운드/복귀 시 딤 잔류·중복·상태바 색상 잔류 없음.
- [ ] 시스템 차단 확인창·OS 공유창 등 OS가 직접 딤을 처리하는 경우 추가 웹/네이티브 딤을 겹치지 않음.
- [ ] 다른 딤 사용 사례도 점검: 일반 게시물/댓글 신고, 바인더 게시물/댓글 신고, 작성·수정, 더보기, 이미지 전체보기, 지도/매물 모달·바텀시트. 의도적으로 딤을 쓰지 않는 UI에 임의로 추가하지 않음.
- [ ] iOS/AOS 실제 단말에서 상태바 → 헤더 → 본문 경계, 밝기, 안전영역 및 기존 뒤로가기 동작 비교 QA.

## 확인한 코드 연결 지점

- `mobile/components/FunyWebView.tsx`: TALK_FORM_OVERLAY_STATE 수신 및 네이티브 헤더.
- `mobile/app/(tabs)/talk.tsx`: 글쓰기 오버레이 상태 전달 경로.
- `mobile/app/web.tsx`: 별도 인앱 페이지에서는 현재 TALK 폼 딤 콜백 연결 없음.
- 웹 `talk-community-v1.js`, `binder.js`: 신고 팝업 열림/닫힘 및 웹 딤.

현재 문서는 다음 빌드 요건만 기록한다. 운영 웹 또는 앱 동작을 변경하거나 빌드를 실행하지 않았다.
