# 관리자 매장 특징 저장 후 표시 누락

## 원인

2026-11-01 확인 당시 shop_features에는 1,194행이 있었지만, 관리자에서 limit/offset 없는 단일 REST 조회로 앞 1,000행만 받았다(Content-Range: 0-999/1194). 저장 RPC는 매장 특징 행을 삭제 후 다시 삽입하므로, 저장된 행이 조회 범위 밖으로 밀려 편집 화면에서 미확인/빈 메모로 보일 수 있었다. 불완전하게 불러온 화면을 다시 저장하면 누락된 특징을 null로 덮어쓸 위험도 있었다.

## 수정

admin.html의 loadAllShopFeatureRows()가 shop_id,feature_id 복합 기본키 순으로 500행씩 조회하여 모두 합친다. 카드샵 관리 로드와 매장 요청 처리용 참조 데이터 로드에 같은 함수를 적용한다. 페이지 오류나 중복 결과가 발생하면 전체 조회를 실패 처리하고 불완전한 결과를 캐시에 반영하지 않는다. 저장 RPC·권한·일반 매장 데이터·다른 연관 정보의 조회는 변경하지 않았다.

## 검증

- 실제 REST 조회: 단일 요청 1,000/1,194행 재현. 분할 요청 500+500+194=1,194행, 복합키 중복 없음. 마지막 빈 페이지도 확인했다.
- node tests/shop-features.cjs: 0/1/499/500/1,000/1,194행 경계, 오류/중복 페이지 거절, 마지막 페이지 매장의 O/X/미확인과 상세 메모 렌더링, 실제 저장 payload 생성, 두 조회 경로 적용 확인.
- tests/shop-feature-save.sql: 실제 admin_save_shop_full RPC로 임시 매장의 true/false/null·메모 저장/변경/초기화와 비관리자 차단 확인. 서브트랜잭션 롤백으로 임시 매장과 연관 데이터를 제거하고 기존 shop_features 해시가 같음을 확인했다. 실매장 데이터를 변경하지 않았다.

관리자 페이지를 새로고침한 뒤 매장 편집을 다시 열어 확인한다. 과거에 잘못 불러온 화면을 저장하여 이미 null로 덮어쓴 값의 자동 복원은 수행하지 않는다. DB에 현재 남아 있는 값을 정확히 불러오는 수정이다. 앱 재빌드는 필요 없다.
