# 쿠폰 발급·확인코드 사용

## 이용 방법

1. 관리자 `/admin-coupons.html`에서 쿠폰명, 혜택·이미지, 매장, 사용 기간, 안내, 발급 한도와 **직원 확인코드**를 등록한다.
2. 확인코드는 숫자 8~12자리다. 관리자에서 8자리 코드를 생성할 수 있으며 매장 직원에게만 별도로 공유한다. 저장한 원문은 다시 조회할 수 없다.
3. 기존 등록 쿠폰은 쿠폰을 선택한 뒤 **직원 확인코드 설정·변경**에서 최초 코드를 설정한다. 기존 발급 쿠폰도 같은 코드가 적용된다. 코드가 없으면 신규 발급·사용을 차단한다. 이미 발급한 쿠폰은 소진하지 않고 그대로 유지한다.
4. 회원은 MY 쿠폰함에서 **쿠폰 사용하기**를 누른다. 팝업에 표시된 쿠폰 코드·상품을 대조하고 매장 직원이 확인코드를 입력한 뒤 **확인**을 누른다. 정상 검증되면 1회 사용 완료된다.
5. 정상 사용 처리 시 팝업이 자동으로 닫히고 쿠폰 카드가 사용 완료로 바뀐다. 카드의 새로고침 버튼은 제공하지 않는다. 사용 기간은 한국 시간 기준 날짜(YYYY.MM.DD)만 표시한다. 네트워크 오류가 나면 팝업의 **사용 상태 다시 확인**으로 서버 상태를 확인한 뒤 필요할 때 재시도한다.

별도 직원 로그인 페이지는 사용하지 않는다. 기존 `/coupon-redemption.html`은 쿠폰함으로 이동한다. 이전 직원 계정 기반 조회·사용 RPC의 클라이언트 실행 권한은 회수했다. 기존 `event_test` 쿠폰과 일반 쿠폰의 표시·정책은 변경하지 않았다.

## 확인코드와 안전장치

- 확인코드는 쿠폰 종류(campaign)별 공통 코드다. 변경하면 기존 발급분에도 새 코드가 적용되며, 이전 코드는 즉시 사용할 수 없다.
- 원문은 공개 테이블, 고객 metadata, 웹 코드, sessionStorage/localStorage에 저장하지 않는다. 비공개 스키마에 bcrypt 해시만 저장하고 관리자에게도 해시는 반환하지 않는다.
- 고객 로그인, 본인 쿠폰 소유권, 쿠폰 종류, 사용 시작·만료, 취소·사용 상태를 서버에서 검증한다.
- 계정·쿠폰 종류별 오입력 5회 시 15분 동안 제한한다. 잘못된 코드 결과는 JSON으로 반환하여 오입력 기록이 트랜잭션 예외로 롤백되지 않도록 한다.
- 행 잠금·상태 검증으로 중복 소진을 방지한다. 사용 완료 후 응답이 유실돼 재시도하더라도 추가 소진하지 않고 사용 완료를 반환한다.
- 고객의 입력값은 마스킹하고 제출·닫기 시 지운다. 처리 결과가 불명확하면 확인 버튼을 잠그고 상태 재조회를 제공한다.
- 감사 metadata에는 `redemption_method=staff_confirmation_code`, 사용 시각, 확인코드 버전을 기록한다. 이 방식은 코드 보유자의 확인이며 실제 직원 신원을 인증하는 방식은 아니다. 확인코드가 고객에게 알려지면 고객도 사용 처리를 요청할 수 있으므로 직원만 관리한다.

## 기존 발급 정책

회원당 같은 쿠폰 1장, 요청당 최대 100명, 총 한도 1~10,000장, 발급 중지, 미사용 발급 취소와 사유·이력, 혜택 스냅샷, 기존 알림 트리거를 유지한다. 쿠폰 이미지·사용 안내·기간·사용 매장을 카드에 표시한다. 사용 완료·취소·만료·사용 예정 상태를 구분한다. 직원 계정 지정 기능은 운영 UI에서 제거하고 확인코드 설정으로 대체했다.

## 검증

- `tests/coupon-issuance.sql`: 해시·권한·소유권·미설정 발급 차단·오입력·정상 사용·중복 재시도·코드 변경·5회 제한·잠금 해제·기간·취소·기존 직원 RPC 차단을 확인한다. 모든 임시 쿠폰·코드·이미지 metadata·알림은 내부 서브트랜잭션 롤백으로 제거하고 기존 쿠폰 해시가 같음을 확인한다.
- `tests/coupon-browser.cjs`: 실제 HTML/JS와 모의 HTTP 응답으로 관리자 코드 설정·신규 등록, 첨부 구성의 카드/팝업, 잘못된 코드·정상·잠금, 응답 유실·오프라인 후 재조회, 입력값 제거, 클라이언트 코드 비저장, 기존 일반 쿠폰 표시, 모바일/PC 넘침을 검증한다.
- tests 의존성 설치 후 Chromium을 준비하고 `node tests/coupon-browser.cjs`로 실행한다. 별도 실행 파일은 `COUPON_BROWSER_EXECUTABLE`로 지정할 수 있다. 선택적 시각 QA 옵션 `COUPON_QA_IMAGE`, `COUPON_QA_FONT_ROOT`, `COUPON_QA_SUPPORT_ROOT`는 제품 의존성이 아니다.

서버 변경은 앱 공통으로 적용되며 `/my-coupons.html` WebView는 최신 파일을 로드하면 반영된다. 네이티브 자체 쿠폰 화면 소스와 iOS/Android 실기기 적용은 이번 작업에서 확인하지 않았다. 해당 화면이 별도 네이티브 구현이면 앱 코드 변경·재빌드가 필요하다.
