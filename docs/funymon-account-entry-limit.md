# 퍼니몬 이벤트 계정 기준 응모 제한

2026-10-23 운영 반영. 원격 migration version: 20261023112218.

## 동작

- `submit_funymon_event_entry`가 서버 발급 응모권의 `funy_mon_catches.user_id`를 사용해 계정을 판별한다. 호출자가 계정 ID를 지정할 수 없다.
- 이벤트 설정의 daily/total/횟수를 계정과 인스타 ID 각각에 적용한다. unlimited 정책은 유지한다.
- 같은 계정이 다른 인스타 ID·다른 응모권을 사용해도 성공한 응모의 합계가 설정 횟수에 도달하면 거절한다.
- 한국 시간 날짜 기준. 성공한 `live_reports`의 응모권을 포획 이력과 연결해 집계하므로 반영 전 성공 이력도 포함한다. 발급·포획만 한 응모권은 차감하지 않는다.
- 계정 → 인스타 순서의 transaction advisory lock을 사용한다. 같은 계정의 다른 인스타 ID 요청도 트랜잭션 종료까지 직렬화한다.
- 기존 `daily_entry_limit` / `campaign_entry_limit` 응답을 유지해 웹·기존 앱 안내가 동작한다. 계정 차단에는 `limit_scope: account`를 추가한다.
- 로그인 토큰이 있으면 응모권의 계정과 일치해야 한다. 기존 웹의 익명 RPC 호출은 유효 응모권 + 클라이언트 증명 경로를 유지한다. 계정 연결이 없는 예전 익명 응모권에는 기존 인스타 제한이 적용된다. 새 포획은 현재 로그인 필수이며 일반 사용자는 포획 테이블에 직접 INSERT할 수 없다.
- 날짜형 캠페인 ID(EV-YYYYMMDD-*)의 직접 EVENT_ENTRY 삽입은 제한적 RLS 정책으로 막는다. RPC의 기존 SECURITY DEFINER/빈 search_path/실행 권한은 유지한다. 예전 EV-CARDVAULT-* 이벤트와 일반 LIVE PIN 삽입은 유지한다.
- 앱 재빌드 및 웹 배포가 필요 없는 서버 변경이다.

## 검증

`tests/funymon-account-entry-limit.sql`은 실제 함수로 정상 최초 응모, 다른 인스타 ID 재응모 차단, 동일 응모권 재사용 차단, 잘못된 응모권 거절, MY 성공 이력 생성, KST 날짜 변경, daily 2회, total 3/4회, unlimited, 계정 불일치, 인스타 중복, 다른 이벤트 독립, 기존 익명 응모권, 실제 계정 advisory lock 보유를 검증한다.

운영 적용 트랜잭션 안에서 검증을 실행했으며 하나라도 실패하면 변경 전체를 롤백하도록 적용했다. 성공한 검증의 모든 캠페인·포획·응모·미션 변경도 별도 subtransaction에서 롤백했다.

추가로 anon 역할에서 날짜형 캠페인 직접 삽입 차단, 기존 이벤트·일반 LIVE PIN 삽입 허용을 확인하고 테스트 변경을 롤백했다.

실제 서로 다른 연결을 통한 동시 요청 부하 시험은 수행하지 않았다. DB에서 계정별 트랜잭션 잠금이 실제 유지되는 것을 확인했다. 기존 응모 이력을 삭제하거나 소급 취소하지 않는다.
