# 바인더 헤더 고정 (2026-10-24)

- 웹의 보관함/자랑하기 목록·상세에서 헤더를 sticky top:0, z-index:80, 흰 배경으로 유지한다.
- 편집기의 editor-fields가 있는 화면은 제외하여 기존 저장 상태 바와 충돌하지 않는다.
- app-shell의 네이티브 헤더와 중복 표시하지 않으며, 사진 전체보기 dialog는 top layer를 그대로 사용한다.
- 기존 web-safe-area가 헤더 높이와 상단 패딩을 맡는다. 별도 여백을 추가하지 않는다.
- tests/binder-header.cjs: 격리 Edge에서 보관함/피드/상세 600px 스크롤 시 y=0, 모사 safe-top 47px에서 높이105px 및 버튼 위치, 가로 넘침 없음, 전체보기 dialog 우선순위, 네이티브 ACK 후 중복 웹/프로필 메뉴 제거 확인. 외부 요청 차단, 운영 DB 쓰기 없음.
- tests/native-share-binder.cjs 기존 공유/메뉴 권한/보관함 순서/TALK 복원 검사 통과.

앱 더보기는 네이티브 route/context 수신 및 렌더 이후 ACK 처리를 보완한 별도 로컬 공통 소스 변경이 있다. 기존 iOS 작업 트리의 미커밋 변경은 건드리지 않았다. 해당 수정은 앱 새 빌드에 포함해야 하며 웹 배포만으로 설치 앱의 네이티브 로직이 교체되지는 않는다. 실제 앱 단말 QA는 남아 있다.

## 한 장 보기 회귀 수정 및 초기 타이틀 — 2026-10-24

기존 검증은 전체 보기로 바꾼 뒤 헤더를 검사하여, 한 장 보기의 html/body overflow-x:hidden이 body를 별도 스크롤 컨테이너로 만드는 충돌을 놓쳤다. 기존 CSS를 주입한 회귀 검사에서 창을600px 스크롤하면 헤더 y=-600으로 실패하는 것을 재현했다.

웹에서만 overflow-x:clip으로 수평 넘침을 차단하며 세로 스크롤 기준을 유지한다. 앱의 기존 hidden 설정은 유지한다. 헤더의 편집기 제외는 DOM 내용 유무가 아닌 진입 view 속성으로 판단하여 로딩 중에도 일관되게 적용한다.

HTML 초기 헤더는 보관함으로 고정되어 있었고 module/auth/data 로드 후에야 자랑하기로 바뀌었다. 이제 헤더 마크업 직후 외부 의존성이 없는 초기 스크립트가 view를 읽어 헤더/문서/네이티브 타이틀 메타를 설정한다. 잘못된 기본 타이틀은 표시하지 않는다.

검증: 기본 한 장 -> 전체 -> 한 장, 실제 창 scrollY>=500, 헤더 y=0, 가로 넘침 없음 통과. binder.js를 지연시킨 상태에서도 detail/feed/mine/edit 타이틀이 처음부터 맞고, 로드 후 타이틀 이력에 다른 문구가 섞이지 않음을 확인했다. 기존 47px 안전 영역, 전체보기 dialog, 편집기 제외 및 네이티브 ACK 검증도 통과. CI의 책장 검사에 헤더/초기 타이틀 회귀 검사도 추가했다. 이 수정은 웹 전용이며 추가 앱 빌드는 필요 없다.
