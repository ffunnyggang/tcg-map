# 바인더 네이티브 헤더 더보기 보완 (2026-10-24)

상태: 공통 iOS/AOS 소스 수정 및 코드 검증 완료. 새 바이너리 빌드·단말 QA 미실시.
기준: work/aos-parity-20261023 / 21c6da09 (Android 내부 테스트 versionCode 10 이후 수정).
별도 작업 트리에서 수정했으며, 기존 iOS 작업 트리의 미커밋 변경은 수정하지 않았다.

## 변경

- 기존 헤더 메뉴는 현재 URL과 수신된 바인더 문맥을 별개로 확인했다. 수신 직후 웹 메뉴를 숨기는 ACK가 먼저 실행될 수 있었다.
- 문맥 수신 시 유효한 바인더 URL을 검증하고 route와 context를 함께 갱신한다.
- 실제 뒤로가기 헤더가 표시되고 해당 바인더 ID가 일치할 때만 메뉴를 표시한다.
- 네이티브 헤더 렌더 이후 effect에서만 ACK를 보내 중복 웹 메뉴를 숨긴다. 다른 화면으로 이동하면 표시 클래스도 정리한다.
- 바인더 URL 재보고가 열린 더보기 드롭다운을 닫지 않도록 했다.
- 동일 출처 CMS wrapper의 target을 해석한다. 외부 URL/잘못된 문맥은 무시하고 개발 localhost는 __DEV__에서만 허용한다.
- 본인: 공유하기 / 자랑 멈추기. 타인: 공유하기 / 신고하기 / 차단하기. 기존 액션·권한 처리는 유지한다.

## 검증 및 남은 항목

- mobile/tests/binder-header.cjs: 실제 onMessage 핸들러와 route/context 도우미 실행. 본인/타인, 미리보기, 서로 다른 ID, wrapper/direct, 잘못된 URL, 조기 ACK 방지, route 재보고 중 메뉴 유지 통과.
- TypeScript noEmit 통과.
- 설치 앱에는 웹 배포만으로 이 네이티브 수정이 적용되지 않는다. iOS/AOS 다음 빌드에 포함해야 한다.
- 연결된 Android 단말 없음. iOS 실기기 미확인.
- 다음 빌드 QA: TALK 전체 인기 바인더, TALK 바인더 탭, 공유 링크, 보관함 경유로 진입. 헤더 우측 더보기 1개, 본문 프로필 우측 중복 없음, 소유자별 메뉴, 클릭 동작, 뒤로가기·다른 바인더 진입·앱 복귀 재확인.
- 웹 sticky 헤더는 별도 work/binder-header-20261024에서 배포한다. 편집기의 저장 상태 바는 영향을 받지 않도록 제외한다.

최종 코드로 iOS/Android Expo JS 번들 export 모두 통과했다. 두 플랫폼 export에서 새 헤더 준비 이벤트 문자열이 포함된 것을 확인했으며, 이는 IPA/AAB 생성이나 설치 앱 반영을 뜻하지 않는다. 늦게 도착한 이전 바인더의 문맥도 현재 route의 바인더 ID와 비교하여 무시한다.
