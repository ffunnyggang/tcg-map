# 더카드룸 테스트 쿠폰 사용 확인 점검
- 점검 기준: main 09808a35 기능, 실제 funy-pin DB 함수/ACL/RLS 확인.
- 기존 RPC는 로그인, 소유권, event_test, 지정 event_id, issued, 유효기간을 검사한다. 단일 조건부 UPDATE라 중복 갱신을 막지만 직원 인증은 없었다. 소유자가 직접 호출 가능했다.
- 기존 UI는 모든 비-issued 상태를 사용 완료로 표시하고 조회 실패를 빈 쿠폰함으로 표시했다. 네트워크 응답 유실 시 서버 성공과 클라이언트 실패를 구분하지 못했다.
- DB 수정: 활성 admin_accounts에 연결된 로그인 사용자만 테스트 이벤트 쿠폰 사용 확정. 고객 소유권 대신 운영자 권한으로 고객 쿠폰을 처리한다. 사용 시각, 처리자 UUID 기록. 일반 쿠폰 및 다른 이벤트는 제외한다.
- inspect_test_cardroom_coupon은 같은 관리자 검증 후 테스트 쿠폰의 상품/코드/상태만 반환한다. 일반 사용자는 호출 불가.
- 고객 화면 직접 사용 버튼 제거. 운영자 확인용 ID 제공. 운영자 전용 페이지에서 코드/상품 대조 후 명시적 확인.
- 이는 FUNY PIN 활성 관리자 확인이며 매장 직원 직책/재직/현장 존재를 증명하지 않는다. 매장 직원 계정은 추가하거나 권한을 부여하지 않았다. 일반 직원에게 전체 관리자 계정을 공유해서는 안 된다.
- 쿠폰 조회 SELECT 권한이 누락되어 있었다. 기존 본인 전용 RLS를 유지하고 authenticated SELECT를 복구했다. 일반 쿠폰 표시 템플릿/사용 정책은 유지한다.
- 검증: 트랜잭션 내 임시 쿠폰으로 소유자 직접 사용 거절, 관리자 정상 사용, 중복/재시도 거절, 만료/일반/미존재 쿠폰 거절, 본인 조회/타 계정 비노출, 비로그인/anon 거절 확인. 임시 쿠폰과 알림 INSERT는 예외 서브트랜잭션 롤백으로 제거했다. 실발급 쿠폰은 수정하지 않았다.
- JS 모의 실행: 전송 전 오류, 서버 성공 후 응답 유실, 타임아웃, 처리 후 조회 오류, 상태 재조회 및 중복 재시도 방지 확인. 실제 단말/실제 패킷 손실 E2E 검증은 하지 않았다.
- 서버 보안 수정은 Web/iOS/Android 클라이언트 모두에 즉시 적용된다. HTML 배포 후 해당 URL을 읽는 WebView는 새로고침으로 적용된다. 이 저장소에는 iOS/Android 네이티브 쿠폰 화면 소스가 없어 앱 화면 경로 및 실기기 반영 여부는 미확인이다. 네이티브 자체 쿠폰 UI면 별도 앱 변경/재빌드가 필요하다.
- 운영자 페이지: /admin-test-cardroom-coupons.html (기존 웹 로그인 사용).
- 실행: node tests/test-cardroom-coupon.cjs
- SQL 회귀 검증: tests/test-cardroom-coupon.sql (임시 데이터는 내부에서 롤백).
