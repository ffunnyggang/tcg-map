UX/UI 구현 기준

WEB · iOS · Android · Admin에서 같은 브랜드 경험을 유지하기 위한 기준입니다. 신규 기능이나 화면을 만들 때 페이지별 임시 스타일을 추가하기보다 이 가이드의 공통 토큰과 컴포넌트를 먼저 사용합니다.

01. 기본 원칙

FUNY PIN은 밝고 캐주얼하지만 유치하지 않은 TCG 수집 서비스형 UI를 기준으로 합니다.

제품 경험

  • 화이트 기반, 낮은 채도의 보라 포인트
  • 게임 UI보다 서비스형 프로덕트 우선
  • 모바일 가독성·터치 영역을 우선
  • 이벤트·퍼니몬은 예외적으로 더 화려한 비주얼 허용

수정 원칙

  • 기존 승인 디자인은 임의 변경하지 않음
  • 공통 컴포넌트가 있으면 페이지별 구현 금지
  • Native/WebView 경계에서 동일 픽셀에 두 레이어를 중복 적용하지 않음
  • 신규 화면 추가 전 이 페이지의 체크리스트 확인

브랜드 로고 · Logo Identity

확정된 FUNY PIN 리뉴얼 로고를 WEB · iOS · Android · Admin · CMS · 인쇄물에서 일관되게 사용합니다. 브랜드 심볼과 워드마크는 디자인 요소가 아닌 승인된 원본 자산입니다.

로고 형태와 사용처

심볼형보라색 그라데이션 지도 핀과 중앙의 흰색 원·가로선이 결합된 확정 형태. 작은 공간, 지도·퀵메뉴·앱 실행 아이콘 등에 사용
가로형심볼 + FUNY PIN 워드마크. 서비스 헤더, 배너, 공식 홍보물에서 우선 사용
세로형심볼 상단 + 워드마크 하단. 정사각형 프로필·소개·브랜드 카드 등 세로 배치가 적합할 때 사용
워드마크원본 FUNY PIN 레터링만 사용. 일반 시스템 폰트나 유사 폰트로 재조판하지 않음

원본 · 컬러 · 배경

원본 우선최종 승인된 로고 원본 SVG/AI 또는 고해상도 투명 PNG를 그대로 사용. 스크린샷에서 추출·AI 재생성·자동 벡터 트레이싱으로 대체 금지
브랜드 컬러로고 전용 기준색 #7B3DFF → #4B00C6 보라 그라데이션(상단 → 하단). 제품 UI 토큰 #8062D8과 용도를 구분
밝은 배경화이트 또는 연한 라벤더 위 컬러 로고를 기본으로 사용
어두운 배경승인된 다크·반전 로고 에셋 사용. 로고의 컬러·그라데이션을 임의로 반전하거나 효과를 추가하지 않음

크기 · 여백 · 정렬

비율심볼·워드마크는 원본 가로세로 비율 유지. 각각의 크기를 조절할 때도 승인된 결합형 배치를 우선
보호 여백로고 주위 최소 여백은 심볼 중앙 원의 바깥 지름 X 이상을 기본으로 확보. 가장자리와 붙지 않도록 배치
작은 크기워드마크 가독성이 떨어지는 영역에는 심볼 단독 사용. 16px·32px·48px·128px에서 선과 원형 요소 식별성 확인
원형 프로필원형 마스킹 영역에 워드마크가 닿지 않도록 텍스트 크기만 조정 가능. 심볼 크기와 위치는 유지하는 별도 프로필용 에셋으로 관리

앱 아이콘 · 배포

iOS1024×1024px 정사각형 마스터와 승인된 다크 변형을 별도로 관리. 라운드 마스킹은 OS가 담당하므로 중복 테두리·그림자 추가 금지
AndroidGoogle Play 스토어용 512×512px PNG와 런처용 Adaptive foreground/background 에셋을 구분. 중앙 안전 영역과 원형·라운드 마스크 미리보기 확인
대표 아이콘작은 화면에서는 심볼형 우선. 서비스명 포함형은 가독성이 확보된 프로필·홍보용 대안으로 사용
배포 규칙브랜드 원본 → 단일 마스터 → 플랫폼별 PNG export. OS별로 로고를 각각 재생성하지 않으며 출시 전 스토어·홈 화면에서 QA

사용 금지 · QA 체크

금지확정 로고의 심볼 구조·중앙 링·가로선·워드마크 폰트·그라데이션을 임의 수정하거나 AI로 재해석
금지비율 왜곡, 임의 회전, 글로우·외곽선·추가 그림자, 브랜드와 무관한 배경 패턴, OS 아이콘별 제각각인 심볼 크기
QA원본 대조 → 밝은/어두운 배경 → 작은 크기 → 원형·라운드 마스크 → 실제 모바일 → 워드마크 외곽선 선명도 순서로 검수
저작권로고 관련 타사 IP 유사성·상표권 및 외부 자산 사용 허락은 별도 검토. 법적 검토 없이 안전성을 단정하지 않음

03. DIM · Modal · Overlay

최상단 바텀시트·모달·팝업은 하나의 modal contract를 사용합니다. 화면 전체는 같은 농도로 보이되, 동일한 물리 픽셀에 DIM이 겹치면 안 됩니다.

표준 결과

전체 화면최상단 overlay 바로 아래에 상태바 · Native Header · Web 콘텐츠까지 끊김 없는 DIM을 표시
농도rgba(20,16,24,.38) — WEB/APP 공통. 기본 blur 없음
입력 차단DIM 아래 화면의 스크롤 · 터치 · 지도 제스처 · 헤더 이전/닫기 · 하단 내비 동작을 차단
DIM 탭DIM 영역 탭은 현재 최상단의 dismissible overlay만 닫고 DIM 상태를 즉시 원복
Overlay 내부바텀시트·팝업 자체의 버튼/입력/내부 스크롤은 정상 동작
적용 범위표준 모달뿐 아니라 이벤트/CMS/사진선택/확인창 등 서비스가 직접 그리는 커스텀 최상단 레이어도 포함

영역 소유권

일반 APPWeb overlay backdrop은 WebView 콘텐츠, FunyNativeOverlayHost는 WebView 밖의 상태바 + Native Header만 담당
Edge-to-edgeWebView가 상태바 뒤까지 실제로 확장된 화면은 Web backdrop이 그 픽셀까지 담당. 같은 상태바에 Native DIM을 추가하지 않음
Native onlyWebView가 없는 Native modal은 Native overlay가 필요한 실제 화면 영역만 한 번 덮음
Stackoverlay가 중첩되어도 backdrop 농도를 누적하지 않음. 항상 현재 최상단 overlay 바로 아래에 시각적 DIM 1겹만 유지

금지 규칙

금지FunyHeader 내부 DIM + Native Overlay Host 동시 적용
금지공통 runtime의 ::before 등 전역 pseudo-DIM 추가
금지SafeAreaView 배경을 어둡게 만든 뒤 DIM을 또 올리는 방식
금지페이지별 rgba · opacity · blur 하드코딩 또는 기존 DIM 위 추가 DIM
금지DIM을 pointer-events:none으로 만들어 아래 화면을 조작 가능하게 두는 방식

명시적 예외

Fullscreen이미지/미디어 viewer는 translucent DIM이 아니라 #09090B edge-to-edge surface
System UIOS 권한·공유 등 시스템이 소유하는 modal은 시스템 동작을 따름
Non-modalToast·비차단 안내처럼 의도적으로 배경 조작을 허용하는 UI에는 DIM을 사용하지 않음
Custom popup이벤트 팝업 · CMS 팝업 · 사진 선택/페이지 편집 팝업 등 커스텀 팝업도 공통 DIM · 입력 차단 · DIM 탭 dismiss 규칙을 동일하게 적용

동작 순서

OPENtop layer 표시 → web backdrop 활성화 → 필요한 Native chrome 영역만 Host에 전달 → background interaction lock
DISMISSDIM 탭/X/완료 → 최상단 overlay 닫기 → Web/Native overlay state reset → 스크롤·상태바 style 원복
Runtimeapp-runtime-fixes-v2.js는 상태를 감지·잠그고 Native에 알릴 뿐 DIM을 직접 그리지 않음
상태바 + Native Header
WebView 콘텐츠 영역
각 픽셀의 소유자가 1겹만 DIM 처리

05. Status Bar · Safe Area

Safe Area는 콘텐츠를 밀어내는 용도와 전체화면 콘텐츠를 확장하는 용도를 구분합니다.

일반 화면Native SafeArea가 상태바 공간을 담당. WebView는 그 아래에서 시작.
전체화면이미지/미디어 viewer는 edge-to-edge로 상태바 뒤까지 확장하고 status bar style만 맞춤.
DIM일반 화면은 FunyNativeOverlayHost가 필요한 Native chrome만 담당. edge-to-edge WebView가 이미 덮는 픽셀에는 Native DIM을 추가하지 않음.
Web Browserweb-safe-area.*가 browser safe-area와 theme-color를 담당.

07. 공통 컴포넌트 규칙

기능별로 아래 패턴을 먼저 재사용합니다.

Modal / Bottom Sheet

  • 표준 DIM 토큰과 공통 overlay contract 사용
  • 열린 동안 배경 스크롤·터치·Native chrome 입력 차단
  • DIM 탭 시 최상단 dismissible overlay 닫기
  • 닫기 시 Web/Native overlay state와 status bar style 원복
  • 바텀시트는 하단 safe area 또는 Native navigation 경계를 반영

Fullscreen Viewer

  • 검정 배경 #09090b
  • 상태바 뒤까지 edge-to-edge
  • 상태바 아이콘은 light-content
  • 닫기 컨트롤은 safe-top만큼 inset

Buttons

  • 최소 터치 높이 44px 권장
  • Primary는 Purple
  • Danger는 공통 danger token
  • 아이콘만 있는 버튼도 accessibility label 필수

WebView

  • Native Header가 있으면 웹 헤더 중복 금지
  • Native UI 변경이 필요한 상태는 bridge event로 전달
  • 웹 CSS만으로 native status bar를 흉내내지 않음
  • route/back은 실제 진입 context를 보존

09. 수정 전 체크리스트

같은 기능의 공통 토큰/컴포넌트가 이미 있는지 확인했는가?
