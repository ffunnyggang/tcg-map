UX/UI 구현 기준

01. 기본 원칙

FUNY PIN은 밝고 캐주얼하지만 유치하지 않은 TCG 수집 서비스형 UI를 기준으로 합니다.

제품 경험

  • 화이트 기반, 낮은 채도의 보라 포인트
  • 게임 UI보다 서비스형 프로덕트 우선
  • 모바일 가독성·터치 영역을 우선
  • 이벤트·퍼니몬은 예외적으로 더 화려한 비주얼 허용

수정 원칙

  • 기존 승인 디자인은 임의 변경하지 않음
  • 공통 컴포넌트가 있으면 페이지별 구현 금지
  • Native/WebView 경계에서 동일 픽셀에 두 레이어를 중복 적용하지 않음
  • 신규 화면 추가 전 이 페이지의 체크리스트 확인

03. DIM · Modal · Overlay

DIM 문제의 핵심 규칙은 “한 픽셀에 한 번만 어둡게”입니다.

표준 규칙

Web 콘텐츠웹 모달·바텀시트의 ::backdrop이 WebView 콘텐츠 영역만 담당
Native ChromeFunyNativeDimLayer가 상태바 + 네이티브 헤더만 담당
농도rgba(20,16,24,.38) — WEB/APP 공통
Fullscreen전체화면 이미지 뷰어는 DIM이 아니라 #09090b 배경 사용

금지 규칙

금지Header 내부 DIM + 상단 Native DIM 동시 적용
금지SafeAreaView 배경을 어둡게 만든 뒤 DIM을 또 올리는 방식
금지페이지마다 다른 rgba 값 사용
허용Web backdrop + Native topChrome DIM처럼 서로 겹치지 않는 영역 분담

시각 기준

상태바 + Native Header
WebView 콘텐츠 영역
웹 모달 backdrop은 여기에서 시작

상단과 콘텐츠가 같은 농도로 보이되, 실제 구현 레이어는 서로 중첩되지 않아야 합니다.

04. Header

앱과 웹의 타이틀·뒤로가기·닫기·더보기 배치를 통일합니다.

공통 수치

  • Header 높이: 54px
  • 좌우 패딩: 14px
  • 타이틀: 19px / 800
  • 뒤로가기 터치 영역: 36×36
  • 더보기: 세로형 ⋮

동작

  • 상세: 왼쪽 이전 버튼
  • 편집/생성 종료: 필요 시 우측 X
  • Native Header가 있는 앱 화면에서는 Web Header 숨김
  • 헤더 자체에서 임의 DIM을 생성하지 않음

05. Status Bar · Safe Area

Safe Area는 콘텐츠를 밀어내는 용도와 전체화면 콘텐츠를 확장하는 용도를 구분합니다.

일반 화면Native SafeArea가 상태바 공간을 담당. WebView는 그 아래에서 시작.
전체화면이미지/미디어 viewer는 edge-to-edge로 상태바 뒤까지 확장하고 status bar style만 맞춤.
DIMNative 상태바 영역은 FunyNativeDimLayer의 topChrome 또는 status scope 사용.
Web Browserweb-safe-area.*가 browser safe-area와 theme-color를 담당.

07. 공통 컴포넌트 규칙

기능별로 아래 패턴을 먼저 재사용합니다.

Modal / Bottom Sheet

  • 표준 DIM 토큰 사용
  • 닫기 시 Native dim state 반드시 reset
  • 바텀시트는 하단 safe area 포함
  • 신고·필터·메뉴 간 동일한 backdrop 농도 유지

Fullscreen Viewer

  • 검정 배경 #09090b
  • 상태바 뒤까지 edge-to-edge
  • 상태바 아이콘은 light-content
  • 닫기 컨트롤은 safe-top만큼 inset

Buttons

  • 최소 터치 높이 44px 권장
  • Primary는 Purple
  • Danger는 공통 danger token
  • 아이콘만 있는 버튼도 accessibility label 필수

WebView

  • Native Header가 있으면 웹 헤더 중복 금지
  • Native UI 변경이 필요한 상태는 bridge event로 전달
  • 웹 CSS만으로 native status bar를 흉내내지 않음
  • route/back은 실제 진입 context를 보존

08. Navigation

뒤로가기는 “어디에서 들어왔는가”를 보존하는 것이 우선입니다.

Native page별도 native route로 push된 경우 native router back 우선
Same WebView동일 WebView 내부 route라면 web history back 우선
Fallbackhistory가 없는 direct entry에만 명시적 fallback 사용
금지상세 화면마다 임의로 HOME/TALK 전체/PICK 전체 등 고정 목적지로 보내기

DIM, 컬러, radius, header 높이를 페이지에서 하드코딩하지 않았는가?
iOS / Android / Web에서 Safe Area와 keyboard 영향을 확인했는가?
뒤로가기 시 실제 진입 화면과 스크롤/필터 상태가 보존되는가?
Native header와 Web header가 동시에 노출되지 않는가?
모달/전체화면 닫기 후 status bar style과 overlay state가 원복되는가?
